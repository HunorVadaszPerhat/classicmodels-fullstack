# Objective 4.2.1 — `@MockBean` vs `@Mock`, `@TestConfiguration`

## The core distinction — context vs no context

This is one of the most tested topics in Section 4. The difference between `@MockBean` and `@Mock` is not subtle — they operate in completely different environments.

**`@Mock`** — Mockito annotation. Creates a mock object. No Spring context involved. Used in pure unit tests with `@ExtendWith(MockitoExtension.class)`.

**`@MockBean`** — Spring Boot test annotation. Creates a Mockito mock AND registers it as a bean in the Spring application context, replacing any existing bean of that type. Used in Spring integration tests with `@SpringBootTest`, `@WebMvcTest`, `@DataJpaTest`.

---

## `@Mock` — pure Mockito, no Spring

```java
@ExtendWith(MockitoExtension.class)  // Mockito only — no Spring context
class OrderServiceTest {

    @Mock
    private OrderRepository orderRepository;  // Mockito mock — not in any Spring context

    @Mock
    private PaymentGateway paymentGateway;

    @InjectMocks
    private OrderService orderService;  // real instance, mocks injected by Mockito

    @Test
    void shouldPlaceOrder() {
        when(orderRepository.save(any())).thenReturn(new Order());
        orderService.placeOrder(new Order());
        verify(orderRepository).save(any());
    }
}
```

No Spring context starts. Fast. Isolated. Tests one class at a time.

---

## `@MockBean` — Mockito mock registered in Spring context

```java

@WebMvcTest(OrderController.class)  // Spring context starts — web layer only
class OrderControllerTest {

    @Autowired
    private MockMvc mockMvc;

    @MockBean  // creates mock AND registers it in the Spring context
    private OrderService orderService;  // replaces the real OrderService bean

    @Test
    void shouldReturnOrder() throws Exception {
        Order order = new Order(1L, "customer-1", BigDecimal.TEN);
        when(orderService.findById(1L)).thenReturn(Optional.of(order));

        mockMvc.perform(get("/sql-script-notes/orders/1"))
                .andExpect(status().isOk())
                .andExpect(jsonPath("$.customerName").value("customer-1"));
    }
}
```

`@WebMvcTest` loads the web layer but not `@Service` beans. Without `@MockBean`, Spring can't wire `OrderController` because `OrderService` is missing from the context. `@MockBean` provides it as a mock.

⚠️ **EXAM TRAP**: `@MockBean` replaces the real bean in the Spring context. If `OrderService` was auto-configured or component-scanned into the context, `@MockBean` removes it and puts a mock in its place. The original bean is gone for that test.

⚠️ **EXAM TRAP**: `@MockBean` invalidates Spring's context cache. Because it changes the context (replaces a bean), Spring can't reuse the same context for a test class that uses `@MockBean` — it creates a new context. This makes tests with `@MockBean` slower than tests that share a cached context.

---

## `@SpyBean` — partial mock in Spring context

The Spring Boot equivalent of Mockito's `@Spy`. Creates a real bean but allows individual methods to be stubbed. The real implementation is called for unstubbed methods.

```java
@SpringBootTest
class OrderServiceTest {

    @SpyBean
    private OrderService orderService;  // real OrderService bean, but stubbable

    @Test
    void shouldUseRealImplementationMostly() {
        doReturn(BigDecimal.ZERO).when(orderService).calculateDiscount(any());
        // all other methods call the real implementation
    }
}
```

---

## Side-by-side comparison

| | `@Mock` | `@MockBean` |
|---|---|---|
| Framework | Mockito | Spring Boot Test |
| Spring context | Not involved | Required — registers in context |
| Replaces real bean | N/A — no context | Yes — replaces existing bean |
| Used with | `@ExtendWith(MockitoExtension.class)` | `@SpringBootTest`, `@WebMvcTest`, etc. |
| Context cache | No effect | Invalidates cache |
| Speed | Fast — no context startup | Slower — context starts |
| Counterpart | `@Spy` | `@SpyBean` |

## `@TestConfiguration`

`@TestConfiguration` defines beans that should be added to (or override beans in) the Spring context **only during tests**. It's a test-only `@Configuration` class.

```java
@TestConfiguration
public class TestPaymentConfig {

    @Bean
    public PaymentGateway paymentGateway() {
        // test-specific implementation — in-memory, no real charges
        return new FakePaymentGateway();
    }
}
```

**Two ways to use it:**

**1. As a nested static class** — automatically picked up by the enclosing test class:

```java
@SpringBootTest
class OrderServiceTest {

    @Autowired
    private OrderService orderService;  // gets FakePaymentGateway injected

    @TestConfiguration
    static class TestConfig {

        @Bean
        public PaymentGateway paymentGateway() {
            return new FakePaymentGateway();
        }
    }
}
```

**2. As a top-level class** — must be explicitly imported:

```java
@TestConfiguration
public class MockServicesConfig {

    @Bean
    public PaymentGateway paymentGateway() {
        return new FakePaymentGateway();
    }
}

@SpringBootTest
@Import(MockServicesConfig.class)  // must explicitly import top-level @TestConfiguration
class OrderServiceTest { }
```

⚠️ **EXAM TRAP**: A nested `@TestConfiguration` class is picked up automatically. A top-level `@TestConfiguration` class must be explicitly imported with `@Import`. This asymmetry is a direct exam question.

---

## `@TestConfiguration` vs `@MockBean` — when to use which

**Use `@MockBean`** when you want a Mockito mock — stubbing, verification, no real implementation needed.

**Use `@TestConfiguration`** when you want a real alternative implementation — a fake, an in-memory version, or a test double with actual logic.

```java
// @MockBean — stub behaviour, verify interactions
@MockBean
private PaymentGateway paymentGateway;  // mock — no real logic

// @TestConfiguration — real test implementation
@Bean
public PaymentGateway paymentGateway() {
    return new FakePaymentGateway();  // real logic — always returns success
}
```

## `spring-boot-starter-test` — what it bundles

The exam asks what this starter includes. The full list:

- **JUnit 5** (Jupiter) — test framework
- **Mockito** — mocking
- **AssertJ** — fluent assertions
- **Hamcrest** — matchers
- **JSONassert** — JSON assertions
- **JsonPath** — JSON path expressions
- **Spring Test** — `MockMvc`, `TestRestTemplate`, Spring test utilities
- **Spring Boot Test** — `@SpringBootTest`, `@MockBean`, `@TestConfiguration`, slice annotations

Everything you need in one dependency. You don't add JUnit or Mockito separately when using this starter.

---

## Plain-English summary

- `@Mock` — Mockito only, no Spring context. Fast unit tests. Paired with `@ExtendWith(MockitoExtension.class)`.
- `@MockBean` — Mockito mock registered in Spring context. Replaces real bean. Invalidates context cache. Paired with Spring test annotations.
- `@SpyBean` — real bean in Spring context with stubbable methods. Spring Boot's `@Spy`.
- `@TestConfiguration` — test-only bean definitions. Nested class = automatic. Top-level class = needs `@Import`.
- `@TestConfiguration` vs `@MockBean`: use `@TestConfiguration` for real test implementations, `@MockBean` for pure mocks.
- `spring-boot-starter-test` bundles JUnit 5, Mockito, AssertJ, Hamcrest, JSONassert, JsonPath, Spring Test, Spring Boot Test.
